1Orientation

Codemare is a DSA practice and learning platform. Learners solve problems in an in-browser editor in Python, JavaScript, TypeScript, C++, Java or Go; a sandboxed judge times their function on the CPU clock to the microsecond; and a tiered learning loop turns solves into topic tokens that unlock new topics through recipes, with timed gate exams opening each tier. Around that sit three Learn tracks, profiles and badges, question authoring, a hidden algorithms library and a Directus admin.

The repository is an npm workspaces monorepo with one root lockfile. Two workspaces deploy; the rest supports them:

  • web/ — the Next.js 15 app the browser talks to: every page, the /api/run|submit streams, server actions, Auth.js, and the domain layer (web/lib/server) over Prisma and two Postgres schemas. It is the only writer of app.*.
  • backend/ — the compile service: a stateless pure executor. The caller sends code plus tests; it compiles and runs them in isolate and streams per-test results and a verdict. No database, no users.
  • admin/ — Directus configuration as code and one extension (the recipe editor), a standalone package outside the workspaces.
  • deploy/ and docker-compose.prod.yml — the one-VPS Compose stack: Caddy, Postgres roles, backups, the runbook.
  • docs/ — the spec it was built against (docs/spec/architecture.md is the source of truth), the decision records and this guide.

Start hereREADME.md for the product, docs/spec/architecture.md for every rule, then a reading path (section 10). The design project's files were never synced into the repo; the spec reconstructs them, and the existing design system in web/app/globals.css and web/components/ui stands in for them.

3Running it

Prerequisites: Node 20+, Postgres 16+, and — to judge every language — Python 3, a JDK (21), g++ and Go 1.22+ on PATH. From the repo root:

npm install
npm run setup          # creates web/.env.local (with a fresh AUTH_SECRET)
createdb codemare      # then set DATABASE_URL in web/.env.local to point at it
npm run setup          # again: Prisma client, migrations, seed
npm run dev            # compile service :4000 + web :4001

Open http://localhost:4001 and create an account. npm run setup is safe to re-run; /dev/system shows the whole design system in both themes. On a machine without isolate (all of macOS) the compile service falls back to the unsandboxed local adapter with a loud warning; production refuses to start in that mode.

TipTest the production build, not just next dev — dev mode has hidden a production-only bug three times now (decision 30 and the bugs section of the decisions page). To build next to a running dev server without sharing its .next (which makes the dev server 404 every chunk), use a separate output folder: cd web && NEXT_DIST_DIR=.next-prod npm run build && NEXT_DIST_DIR=.next-prod npx next start -p 4002. That build rewrites web/next-env.d.ts and web/tsconfig.json for the other folder; restore them afterwards with git checkout web/next-env.d.ts web/tsconfig.json.

Directus locally: docker compose up -d --build gives Postgres on 127.0.0.1:5433 and Directus on :8055; --profile app adds the web app (:3000) and the compile service (:4100) in containers. The production stack and its runbook are in deploy/README.md.

5Data model

One Prisma schema, two Postgres schemas. content.* is what staff edit in Directus and the seed writes: questions, the learning loop, badges, Learn and the Library. app.* is everything a user does, written only by the web app's server code. The arrows are the foreign keys that cross the boundary — nearly all of them point from a user's record to the content it is about.

content.* — 17 tables

TableHolds
tiersTier order (ord 0 is the free tier), slug, title, summary.
topicsThe ten topics, each in one tier, with an icon from the shared vocabulary.
unlock_recipes, recipe_itemsA topic's alternative ways to unlock; an item is token topic × quantity (> 0) × minimum source difficulty.
questionsStatement, examples, constraints, signature, compare mode, starter code, tests and reference solutions (JSON; the references never reach a learner), status, limits, optional author.
question_topicsQuestion × topic with a weight: its share of the solve award. Composite questions span tiers.
hintsFive levels per question, each costing score or tokens.
gates, gate_questionsThe timed exam that opens a tier: pass threshold, 12–24 h cooldown, time limit; its ordered questions.
badges15 badges with rarity and JSON criteria.
tracks, learn_modules, lessons, checkpoint_questionsLearn: tracks → modules → lessons (markdown with directives) and each module's quiz.
library_areas, library_chapters, library_articlesThe hidden algorithms library.

6Routes and actions

Login means the middleware's wall: a signed-out page request goes to /signin?next=… and a signed-out API call gets a 401 JSON. Checks marked (DB) re-read the user's role from Postgres rather than trusting the JWT, so a demotion takes effect at once; "404" means the same response an unknown URL gets, so nothing can be probed.

7Safety rails

The guards in place today. Each exists because of a specific bug or threat — the decisions page tells those stories.

A sandbox per boxbackend/src/services/sandbox/isolateCommand.tsFresh isolate boxes per request: private mount, PID, network and IPC namespaces; --cg-mem 256 MB; one CPU as a cpuset; PID caps per language; 16 MB per file; no core dumps; the strict syscall filter; an explicit three-variable environment; a tmpfs box root.
No route outdocker-compose.prod.ymlThe compile service and Postgres sit only on an internal: true network; Caddy publishes the only ports. The compile service runs as uid 10001; only the setuid isolate binary is root.
Internal tokenbackend/src/middleware/internalAuth.ts · web/lib/compile.tsTiming-safe compare; production refuses a missing or placeholder value on either side. Never in the browser, never inside a box (isolate itself is started with PATH only).
Login wall, fail-closedweb/middleware.ts · web/components/Auth/routes.tsJWT decoded on the Edge; signed-out API calls get 401 JSON; any auth error is treated as signed out; ?next= accepts same-origin paths only.
Rolesauthor/viewer.ts · library/viewer.ts · submissionHistory.tsThe role rides in the JWT for navigation; authoring, the library and other people's submissions re-read it from the database. Denied is the same 404 as unknown.
Rate limitsweb/lib/rateLimit.tsLogin 10/15 min per IP and 5 per email; sign-up 5/h per IP; reset flows per IP and email; one judge budget of 30/min per user shared by run, submit, IDE, snippets and reference runs; AI review 12/h. The compile service keeps only a 6000/min circuit breaker.
Size capsweb/lib/server/runner.ts · backend/src/services/runValidation.tsWeb: 64 KB source, 512 KB body, 8 custom inputs. Compile service: 64 KB code, 256 KB prelude, 200 tests, 4 MB of tests, 6 MB body, limits capped at 10 s and 512 MB; the compile cache holds at most 256 entries and COMPILE_CACHE_MAX_MB (1 GiB) on disk and in memory.
Hidden tests stay hiddenweb/lib/server/runner.ts · rules/testResults.tsNo input, expected or output leaves the server; a hidden test's error is cut to its exception class. For Python, JS, TS and Go the expected values never enter the box.
Ledger guards in the databaseweb/prisma/migrations/…_integrity_guardsAn append-only trigger, an earn-once partial unique index, amount ≠ 0; spends re-read balances under a per-user advisory lock and write nothing on a shortfall.
Directus confined by Postgresdeploy/postgres/db-init.sql · content-integrity hookThe directus role has row DML on content.* only: no DDL, no app.*. The hook re-checks recipe, weight and gate rules for every client.
Hidden librarylibrary/viewer.ts · web/app/robots.tsStaff only unless the flag is on; the 404 matches an unknown URL; noindex on every page, a robots Disallow, no links from anywhere.
Untrusted markdownweb/lib/lesson-markdown · Problem/Markdown.tsxCMS-edited content renders through rehype-sanitize with no raw HTML, an http(s)/mailto/relative URL allowlist, allow-listed directive attributes and bidi characters stripped from code.
Secretsdeploy/.env · deploy/secrets/Mode 600 and git-ignored; generated with openssl rand; reset tokens stored as hashes, passwords as bcrypt; backups encrypted by restic before they leave the VPS.
Production guardssandboxService.ts · app/dev/layout.tsx · passwordReset.tsThe local adapter refuses NODE_ENV=production; /dev is a 404; reset links take AUTH_URL's origin, not the Host header.

9Status board

Done and verified

  • Judging in six languages through /v1/run and SSE, with µs CPU timing and per-test results
  • The learning loop: ledger, recipes, unlocks, gates with cooldowns, the hint ladder
  • The Queue and My Library removed at the owner's request (decision 38): migration, Directus clean-up, and the economy re-simulated with questions as the only earn — no dead ends
  • Learn (3 tracks, 23 lessons), profiles, 15 badges, authoring with a re-verified publish, the hidden library
  • Directus confined by Postgres roles, with editable join tables and the two seed modes
  • Sandbox hardening proven in the production image (the 26-check smoke runs in CI); the compile cache bounded by bytes as well as entries
  • The legacy compile-service surface removed: the web app and the compile service speak only /v1/run, /v1/run/stream and IDE mode
  • The Compose stack, backups and a restore drill, verified locally end to end
  • CI: six jobs, including Playwright against a production build
  • Accessibility and first paint: no axe violations on any audited view in either theme, gated by a Playwright spec; LCP about 1.4 s on the catalog and the editor with throttling applied

Known gaps

  • The design project's files are not synced (/design-sync); screens follow the spec's reconstruction and must be reconciled — the design files win on conflict
  • Directus asks a project owner to accept its license and DPA on first login: the deployment owner's call
  • Java's runUs counts only the calling thread; work handed to other threads is untimed
  • amd64 builds of the web, Directus and backup images, and a real Storage Box, are untested (local verification ran on Apple silicon with an SFTP stand-in; CI builds only the backend image)
  • Rate limits are in-process (one web instance); the Redis queue does not serve /v1/run
  • Directus keeps inert field and relation meta of the Queue's dropped tables; tidying them is an optional SQL step (deploy/README.md §7.3)
  • The brief's LCP < 2 s is met with throttling applied on localhost (about 1.4 s) but not in Lighthouse's simulation (about 2.6 s); confirm it on the deployed VPS

Next

  • Sync the design files and reconcile every screen against its artboard
  • First production deploy: license decision, amd64 images, a restore drill against the real Storage Box, an LCP check on the real host
  • Time Java across threads, or say in the UI that only the calling thread counts
  • User-authored books and monetization (docs/authoring-v1.md) — not started
